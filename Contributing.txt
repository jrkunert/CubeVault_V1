# Contributing to CubeVault

Thank you for contributing to CubeVault.

This project follows a governance-first engineering model. All contributions must align with the project's governing documentation before implementation begins.

---

# Before You Start

Contributors should review the following documents in order:

1. CubeVault Constitution
2. CubeVault Project Manifest
3. CubeVault Architecture Guide
4. CubeVault Engineering Standards
5. Current Recovery Package

These documents define the project's governance, architecture, engineering methodology, and current state.

---

# Development Principles

Contributors are expected to:

- Follow the approved architecture.
- Follow the Engineering Standards.
- Keep documentation current.
- Maintain repository organization.
- Produce production-quality work.
- Avoid speculative implementation.
- Record significant architectural decisions.

---

# Branching

Use feature branches for implementation work.

Example:

feature/m1-b01-solution-foundation

Avoid committing directly to the main branch except through the approved review process.

---

# Pull Requests

Each pull request should:

- Have a clearly defined scope.
- Reference the related milestone and batch.
- Include documentation updates when appropriate.
- Pass all automated validation.
- Be reviewed before merging.

---

# Code Quality

All code should:

- Be readable.
- Be maintainable.
- Follow naming conventions.
- Include appropriate tests.
- Respect architectural boundaries.
- Avoid unnecessary complexity.

---

# Documentation

Documentation is a required project artifact.

When implementation changes behavior, update the appropriate documentation alongside the code.

---

# AI-Assisted Development

AI-assisted development is supported.

AI-generated content must:

- Comply with project governance.
- Follow the Architecture Guide.
- Follow the Engineering Standards.
- Be reviewed by a human before acceptance.

---

# Questions

When uncertainty exists, defer to the governing documentation rather than making assumptions.

If conflicts are identified, follow the document authority hierarchy established in the CubeVault Constitution.

---

Thank you for helping maintain the quality and consistency of CubeVault.
